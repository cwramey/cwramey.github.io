Pulling Footage & Pole Counts from Telecom Design PDFs

Telecom design sheets are full of numbers a permit team needs: fiber footage, duct sizes and lengths, pole counts, handhole tallies. The problem is where those numbers live: scattered across a multi-page PDF in callouts, legends, and summary tables, in a layout designed for a human with a highlighter, not a database.

Reviewing one by hand is 20–30 minutes of careful counting. PyMuPDF (imported as fitz) turns that into seconds. Here's the approach.

1. Open the PDF and pull its text

PyMuPDF reads the text layer of a PDF directly, with no OCR needed as long as the PDF has real text (most CAD/design exports do). Start by concatenating the text of every page:

import fitz  # PyMuPDF

doc = fitz.open("design_sheet.pdf")

text = ""
for page in doc:
    text += page.get_text()

If a sheet is a scanned image with no text layer, get_text() comes back empty. That's your signal to route it through OCR first. Worth checking for explicitly so a scanned page doesn't silently report zero footage.

2. Match the measurements with regex

Design callouts are remarkably consistent within a given standard: something like 1,250 LF for linear feet of fiber, or (2) 2" PVC for duct. That regularity is exactly what a regular expression is for:

import re

# Linear footage: "1,250 LF" or "1250 ft"
footage = re.findall(r"([\d,]+)\s*(?:LF|FT|ft)\b", text)
total_lf = sum(int(f.replace(",", "")) for f in footage)

print(f"Total fiber footage: {total_lf:,} LF")

The same idea handles duct measurements: capture the count, the size, and the material in named groups so the result is structured, not just a string:

duct_pattern = re.compile(
    r'\((?P<count>\d+)\)\s*(?P<size>\d+(?:\.\d+)?)"?\s*(?P<material>PVC|HDPE|RGS)'
)

ducts = [m.groupdict() for m in duct_pattern.finditer(text)]
# -> [{'count': '2', 'size': '2', 'material': 'PVC'}, ...]

3. Count poles without double-counting

Poles are usually labeled (P-101, P-102…), and the same pole often appears on more than one sheet where routes overlap. Counting every match inflates the total. Collect the identifiers into a set instead, so each pole is counted once no matter how many times it's drawn:

pole_ids = set(re.findall(r"\bP-\d{3,}\b", text))
print(f"Unique poles: {len(pole_ids)}")

The recurring lesson in document parsing: count unique entities, not raw matches. A regex that finds "every pole label" and one that finds "every distinct pole" give very different (and only one correct) answers.

4. Use position when text order fails

Sometimes the plain text comes out jumbled because the PDF stores fragments in draw order, not reading order. When that happens, ask PyMuPDF for the text with coordinates and use position to reconstruct meaning, for example to find the value sitting just to the right of a label:

for page in doc:
    words = page.get_text("words")  # (x0, y0, x1, y1, "word", ...)
    for w in words:
        x0, y0, x1, y1, word = w[:5]
        if word == "TOTAL":
            # grab words on the same line, to the right
            same_line = [t for t in words
                         if abs(t[1] - y0) < 2 and t[0] > x1]
            print("TOTAL ->", [t[4] for t in same_line])

This is the difference between a parser that breaks on the first oddly-formatted sheet and one that holds up across a whole project's worth of them.

5. Emit structured output

With the numbers captured, the last step is to hand them off in a form the next system can use: a dict that becomes JSON for an API, or rows for a spreadsheet the permit team already lives in:

summary = {
    "total_footage_lf": total_lf,
    "ducts": ducts,
    "pole_count": len(pole_ids),
}

import json
print(json.dumps(summary, indent=2))

Why it's worth it

A person reviewing a design sheet is slow not because the work is hard, but because it's tedious and unforgiving: one miscounted pole or transposed digit and the permit is wrong. A parser does the boring part identically every time, leaving the reviewer to do what they're actually good at: catching the cases that don't fit the pattern.
